# فاز ۱۷ — به‌روزرسانی تست مرجع Integration Host

**دامنه:** این اصلاحیه فقط فایل تست مرجع `IntlPhase12ReferenceFlowTest.php` و مستندات فاز ۱۷ را تغییر می‌دهد. موتور Workflow، Billing، Service Recipients، Service Requests و کد NCR دست‌نخورده باقی می‌مانند.

## علت تغییر

تست قدیمی فاز ۱۲ مربوط به APIهای قبل از اصلاحات فازهای ۱۳ تا ۱۵ بود و دیگر مرجع یکپارچگی معتبر محسوب نمی‌شود. اصلاحیه جدید مطابق کدهای آرشیوی مرورشده ساخته شد؛ پشتیبانی از اینترفیس‌های فعلی پیش‌نیاز اجرای آن است.

- ایجاد رکورد واقعی و **رمزگذاری‌شده آزمایشی** در جدول محلی `intl_recipients`، نه تأیید مالکیت صرفاً با Fake؛ اعتبارسنج اضافهٔ میزبان همچنان خطای خود را به‌شکل fail-closed اعلام می‌کند.
- افزودن Policy صریح `request_management` به تنظیمات Service Catalog و قراردادهای ضروری `RequestAudit` و `RequestSubmissionVerifier`؛ هر دو به‌صورت Fake محدود و قابل بررسی تعریف می‌شوند. رویدادهای Audit انتخاب‌شده از طریق Spatie و در همان DB آزمایشی ثبت می‌شوند.
- انتقال درخواست اصلاح و ارسال مجدد به API اختصاصی `RequestLifecycle` و آزمایش محدودیت ویرایش فیلدها و مدارک.
- جایگزینی فراخوانی قدیمی `dispatch($paymentId)` با `dispatch($id, $amount, $currency, $revision)`؛ آزمایش `Unknown -> Reconcile -> Succeeded` و ممنوعیت برداشت یا Retry در حالت نامشخص.
- افزودن سناریوی شکست قطعی بدون برداشت، تغییر قیمت ثابت در **Service Catalog محلی**، ایجاد تلاش دوم با قیمت جدید و حفظ مبلغ تلاش اول.
- آزمایش تقاضای لغو، ممنوعیت تأیید متعارض، رد تقاضا بدون تغییر وضعیت اصلی و پس‌گرفتن تقاضا توسط نمایندگی.

## محدودیت‌ها و مرز امنیتی

- Fakeهای این تست به هیچ API حقیقی متصل نمی‌شوند و جایگزین Policy احراز هویت، اسکنر بدافزار، قیمت‌گذاری عملیاتی و Gateway معتبر نیستند.
- تست حاضر مسیر پرداخت **بعد از تأیید** را نشان می‌دهد؛ تست کامل استرداد بعد از پرداخت پیش از بررسی، احراز اختیار نماینده حقوقی و قطعی سامانه خارجی همچنان باید در سناریوهای میزبان جداگانه اضافه شوند.
- تاریخچه پرداخت و RefundPolicy در این نسخه براساس تعریف موقت Service Catalog آزمایشی خوانده می‌شوند؛ شیوه نگهداری واقعی، قرارداد استعلام پیشخوان مرکزی، واحد پول و امنیت پاسخ‌ها هنوز به مشخصات رسمی API نیاز دارند.
- موفقیت این تست روی SQLite، رفتار هم‌زمانی DB مقصد و Storage واقعی را اثبات نمی‌کند.
- **این اصلاحیه هیچ Migration یا تغییر عملیاتی ندارد.**

## پیش‌نیاز نصبِ موکول‌شده

۱. ابتدا پچ‌های اصلی به ترتیب بسته فاز ۱۶ اعمال شده باشند؛ بخصوص فازهای ۱۳ تا ۱۵ و تنظیمات/مهاجرت‌های Spatie Permission و Activitylog.

۲. پس از اعمال پچ مرجع فاز ۱۲ **فقط یک بار**، پچ فاز ۱۷ را اعمال کن. اگر در فایل تست مرجع خودت تغییرات محلی داشتی، فایل را کورکورانه بازنویسی نکن؛ ابتدا diff بگیر.

۳. پیش از اعمال، در ریشه پلتفرم اجرا کن:

```bash
# فایل را در ریشه intl-platform بگذار
git apply --check intl-phase17-reference-host-v2.patch
git apply intl-phase17-reference-host-v2.patch
```

۴. در Sandbox آزمایشی مستقل (نه NCR و نه دیتابیس عملیاتی)، Composer dependency و Migrationهای مربوط به پکیج‌های قبلی باید نصب باشند؛ سپس:

```bash
cd apps/sandbox
php artisan test --filter=IntlPhase12ReferenceFlowTest
php artisan test
```

۵. اگر تست جدید قرمز بود، **کنترل‌ها را برای سبزکردن تست حذف نکن**. خروجی کامل اولین شکست و `composer show` مربوط به پکیج‌ها را بررسی کن.

## وضعیت فعلی تأیید

بازبینی در محیط ساخت پچ: بررسی نحوی PHP، تطبیق امضاهای روش‌های اصلی با سورس آرشیوی و بازپخش پچ در ساختار ایستای فاز ۱۶. این موارد **جایگزین اجرای PHPUnit و Laravel واقعی نیستند**. وضعیت نهایی «آماده تستِ Sandbox پس از نصب مرحله‌ای»، نه آماده تولید.

### بررسی سریع قراردادها پس از اعمال پچ‌ها

```bash
php tools/phase17/verify-reference-contracts.php
php -l apps/sandbox/tests/Feature/IntlPhase12ReferenceFlowTest.php
```

ابزارِ اول فقط وجود و امضاهای ۱۴ API و اعتبار ساختاری دو تعریف Policy را بررسی می‌کند؛ **تست یکپارچگی Laravel نیست**.
