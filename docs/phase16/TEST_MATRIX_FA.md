# ماتریس تست اولویت‌دار فاز ۱۶

| شناسه | حوزه | سناریو | نتیجه مورد انتظار |
|---|---|---|---|
| T01 | Packaging | بازپخش همه پچ‌ها در فولدر خالی | `git apply --check` و نصب پچ‌ها بدون تداخل |
| T02 | Composer | همه Core/Adapterها و حداقل ثبات | وابستگی محلی گمشده/چرخه نداشته باشد؛ `minimum-stability` کل پروژه شل نشود |
| T03 | Core | همه PHPUnitهای مستقل (Workflow, Catalog, Forms, Documents, Billing, Requests, Recipients) | صفر شکست |
| T04 | Laravel | تمام تست‌های Adapter از جمله Spatie Permission/Activitylog | صفر شکست؛ هیچ Permission خودکار اضافه نشود |
| T05 | Reference Host | بازنویسی تست فاز ۱۲ مطابق قرارداد Billing14/Requests15/Recipients13 | جریان اصلی و منفی end-to-end سبز شود |
| T06 | Access | نمایندگی A نتواند مشتری/پرونده نمایندگی B را حدس بزند | رد دسترسی و عدم افشای وجود رکورد |
| T07 | Recipient | تغییر شناسه با مجوز ادمین + همگام‌سازی همه فیلدهای پروفایل در Draftهای مجاز | درخواست‌های ارسال‌شده بدون تغییر بمانند |
| T08 | Archive | آرشیو مشتری با Draft آزاد ولی با درخواست جاری ممنوع | Draftهای پیش از آرشیو حتی پس از restore فقط‌خواندنی |
| T09 | Cancellation | Draft فوری؛ بعد از ارسال نیازمند تأیید؛ انصراف یا رد | حفظ حالت و مجوز اصلاح قبل از تقاضای لغو |
| T10 | Concurrency | همزمانی تأیید ادمین/لغو و انصراف/تصمیم | فقط یکی اعمال شود؛ تاریخچه صحیح |
| T11 | Correction | اصلاح کامل/محدود و بی‌نهایت دور؛ تلاش ویرایش مستقیم غیرمجاز | فقط فیلدها/مدارک مجاز همان نوبت تغییر کنند |
| T12 | Price | شکست قطعیِ بدون برداشت و سپس تغییر قیمت خدمت | تلاش تازه با قیمت جدید و تأیید دوباره نمایندگی؛ سابقه تلاش قدیمی محفوظ |
| T13 | Unknown Payment | Timeout پس از برداشت احتمالی و تلاش دوباره | بدون برداشت دوم؛ lookup همان عملیات اولیه |
| T14 | Refund | رویداد مجاز، استرداد کامل و حالت‌های automatic/admin/manual | نبود استرداد جزئی و دوباره؛ نتیجه مرکزی معتبر لازم |
| T15 | Legal Rep | هر درخواست حقوقی یک نماینده؛ اعتبار قبلی یا بررسی مجدد طبق سازمان | وضعیت خطا/قطعی خارجی fail-closed؛ snapshot تاریخی |
| T16 | Documents | Failure after storage write/DB rollback | فایل یتیم پاک‌سازی یا برای جبران قابل ردیابی باشد |
| T17 | Audit | اقدامات امنیتی، پرداخت، تغییر شناسه، لغو، آرشیو | ثبت هم‌تراکنش بدون نام، شناسه هویتی، توکن و مدارک |
| T18 | Operations | Worker lookup، مانیتور پرداخت unknown، Recovery | هیچ اقدام خارجی با شناسه مبهم تکرار نشود |

هیچ‌یک از سناریوهای بالا را فقط با بررسی نحوی PHP «Passed» محسوب نکن. تست DB مقصد در محیط آزمایشی مستقل سازمان لازم است.
