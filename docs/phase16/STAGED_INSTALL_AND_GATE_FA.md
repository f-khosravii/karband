# راهنمای نصب مرحله‌ای و دروازه‌های تأیید — فقط هنگام فراهم‌شدن محیط توسعه

**اکنون اجرا نکن.** در مخزن کاربر فایل‌های staged، modified و untracked زیادی گزارش شده بود. روی شاخه موجود بدون Snapshot معتبر، `git reset --hard`، `git clean`، `stash` و `migrate:fresh` انجام نده. ZIP و Patch یک فاز را با هم اعمال نکن؛ اصلاح تست Documents را که قبلاً دستی انجام شده دوباره اعمال نکن.

## ترتیب منطقی نسخه‌های نهایی

1. مبنای نصب‌شده و تست‌شده: `intl/contracts`، Workflow Core/Adapter، Authorization/Spatie Permission، Service Catalog، Dynamic Forms و Documents. تست‌های گزارش‌شده قدیمی مبنای Regression هستند، نه تأیید همه فازهای جدید.
2. پچ اصلی فاز ۸ Billing، سپس **اصلاحیه فاز ۱۴**؛ پس از انجام Migration افزایشی *فقط روی Sandbox*، تست‌های مستقل Billing و تست‌های Billing Laravel. برای `dev-main`، Core و Adapter و وابستگی‌های محلی را در Composer ریشه مناسب صریح اضافه کن.
3. پچ اصلی فاز ۹ Service Requests. این نسخه میانی را جداگانه تست کن و قبل از فاز ۱۵ به‌عنوان نسخه عملیاتی استفاده نکن.
4. پچ فاز ۱۰ Audit/Spatie Activitylog (می‌تواند پیش از ۲ و ۳ نیز اضافه شود). تنها یک Migration Activitylog؛ تنظیم درست causer/subject id؛ بدون فعال‌سازی خودکار لاگ حساس.
5. پچ فاز ۱۱ فقط مستندات و ابزار بررسی؛ در صورت نیاز.
6. پچ فاز ۱۳ Service Recipients و پیش‌نیازهای اختصاصی آن (HMAC پایدار، رمزگذاری، اتصال محلی به همان DB، قانون اختصاصی هر سازمان). تست مستقلی/یکپارچه.
7. پچ اصلاحی **فاز ۱۵ Service Requests** پس از نصب فاز ۹، ۱۳ و ۱۴. تست‌های جدید لغو، اصلاح، آرشیو پیش‌نویس، یکپارچگی مشتری و تلاش مجدد.
8. **فاز ۱۲ فعلی را در مجموعه نهایی اجرا نکن مگر پس از ساخت Reference Host v2** بر مبنای Billing 14، Service Requests 15 و Recipient 13. اجرای تست‌های دیگر نباید به‌صورت ساختگی مانع مهم را پنهان کند.
9. پس از تعمیر تست مرجع، مجموعه کامل Sandbox + core + تست رقابتی DB مشابه مقصد + Security Gate + مستندات API پیشخوان. سپس نسخه‌بندی محدودشده (نه `dev-main`) و انتشار مستقل در هر سازمان.

## نسخه بدون دست‌کاری مخزن

برای بازپخش **ایستای پاک** می‌توان از `tools/replay-clean.sh /path/to/EMPTY/temporary-folder` داخل همین بسته استفاده کرد. اسکریپت فقط دایرکتوری خالی مشخص‌شده را مقداردهی می‌کند؛ از آن به‌عنوان دستور نصب پروژه واقعی استفاده نکن. `fixtures/contracts/composer.json` فقط نقشه PSR-4 پکیج موجود کاربر را شبیه‌سازی می‌کند و هیچ تابع عملیاتی ندارد.

## دروازه‌های عبور

| Gate | معیار پذیرش | اکنون |
|---|---|---|
| G1 Source Replay | همه پچ‌ها روی اسکلت پاک و syntax/گراف Composer | ایستا بررسی شده |
| G2 Package Tests | PHPUnit اختصاصی همه Coreها و تست هر Adapter | فازهای ۱۳–۱۵ نیازمند اجرا |
| G3 Full Regression | تمام تست‌ها شامل Reference Host v2 | بلوکه: Phase 12 قدیمی |
| G4 Trust/Security | سیاست نمایندگی، سه نقش، Audit غیرحساس، فایل‌اسکنر واقعی، HMAC/رمزنگاری | نیازمند Host |
| G5 Concurrency | لغو/تأیید هم‌زمان، تغییر هویت/ایجاد درخواست، شکست پس از ذخیره فایل، DB مقصد | اجرا نشده |
| G6 Finance | قرارداد واقعی Idempotency و Lookup پیشخوان و استرداد کامل | اجرا نشده |
| G7 Release | قفل‌کردن نسخه‌ها، Migration قابل بازگشت، Snapshot و راهنمای مستقل هر سازمان | معوق |

**هشدار:** ابزار `verify-structure.php` صرفاً بررسی ایستا انجام می‌دهد؛ کدهای Laravel را boot نمی‌کند و هیچ تست Runtime جایگزین نمی‌شود.
