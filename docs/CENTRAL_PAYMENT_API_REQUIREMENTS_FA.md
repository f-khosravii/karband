# اطلاعات موردنیاز برای ساخت Adapter واقعی پرداخت مرکزی پیشخوان

این فایل فهرست اطلاعاتی است که **قبل از هر اتصال عملیاتی** باید از تیم API مرکزی دریافت شود. هیچ‌کدام از موارد زیر را حدس نزنید.

1. مشخصات احراز هویت ماشین‌به‌ماشین (نوع توکن/امضا، چرخش کلید، IP allowlist در صورت نیاز، محیط تست، TLS و تایید سرور).
2. endpoint و نمونه **واقعی** request/response برای ایجاد یک پرداخت (شناسه پایدار درخواست، شناسه نمایندگی در سیستم مرکزی، شناسه پرونده/خدمت، مبلغ و واحد پولی).
3. تضمین قراردادی Idempotency: چه اتفاقی می‌افتد اگر دو بار **همان کلید** را ارسال کنیم؟ کلید چه مدت حفظ می‌شود؟ کلید در تمام مایکروسرویس‌ها چه Scopeای دارد؟
4. endpoint استعلام نتیجه قطعی **با همان کلید درخواست**، سازگاری تأخیری و معنای دقیق پاسخ `not_found`.
5. معنای دقیق هر وضعیت و خطا: کدام پاسخ واقعاً «عدم برداشت قطعی» است، کدام نیازمند استعلام و کدام به معنای موفقیت قطعی با شماره پیگیری معتبر است؟
6. واحد مبلغ: ریال یا تومان یا واحد فرعی دیگر، تعداد رقم/سقف، نوع Currency، مرجع قیمت خدمت و نحوه تطبیق صورتحساب.
7. timeout، retry-after، محدودیت نرخ API، وب‌هوک (اگر دارد) و نحوه اعتبارسنجی امضای وب‌هوک.
8. تضمین‌های مربوط به آشتی روزانه، دریافت گزارش مرجع مرکزی، اختلاف حساب، بازگشت وجه/Refund و رصد مغایرت.

**قانون اجرایی:** تا زمانی که بندهای ۳، ۴ و ۵ به‌طور قابل آزمون مشخص نشده‌اند، Binding عملیاتی `CentralPaymentGateway` و Dispatch واقعی فعال نشود. برای Sandbox فقط Fake استفاده می‌شود. مایکروسرویس همچنان صرفاً با `PaymentCommand` و `PaymentOutcome` تعامل می‌کند؛ هیچ موجودیت کیف پول وارد مدل INTL نمی‌شود.
