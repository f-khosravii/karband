# فاز ۱۲ INTL — Reference Host Integration Test Kit

**وضعیت:** بسته کد و تست برای ادغام آینده، نه یک استقرار جدید و نه تأیید Production. این بسته عمداً پکیج مشترک یا دیتابیس فعلی را تغییر نمی‌دهد.

## هدف و مرزها

این فاز به‌جای ساخت موتور تازه، یک تست مرجع در `apps/sandbox/tests/Feature/IntlPhase12ReferenceFlowTest.php` اضافه می‌کند که پکیج‌های موجود را به کمک پیاده‌سازی‌های میزبانِ **صرفاً آزمایشی** به هم وصل می‌کند:

- انتشار Workflow مستقل خدمت، کاتالوگ محلی، فرم و الزامات مدارک توسط ادمین مایکروسرویس؛
- ثبت درخواست مشتری غیرکاربر از طرف نمایندگی و Pin شدن نسخه‌های تعاریف؛
- ممنوعیت Submit پیش از تکمیل فرم و مدارک، درخواست اصلاح با توضیح، جایگزینی مدرک فقط در وضعیت مجاز، باز‌ارسال و تأیید توسط ادمین همان سازمان؛
- ساخت قصد پرداخت محلی فقط پس از تأیید؛ شبیه‌سازی موفقیت پرداخت با از دست رفتن پاسخ، `unknown` و بازیابی از طریق `lookup` **بدون درخواست برداشت دوم**؛
- انتقال به صدور فقط پس از تأیید پرداخت؛ ثبت Audit گزینشی با داده‌های غیرحساس؛ بررسی عدم دسترسی نمایندگی دیگر و رفتار fail-closed در خرابی مرجع مشتری.

در این تست سه نقش مستقیم تعریف می‌شوند: `agency`, `government_admin`, `platform_admin`. مشتری فقط `RecipientReference` است. برای واقعی‌تر شدن سناریوی دسترسی، دو حساب آزمایشی جداگانه برای دو نمایندگی وجود دارد. هر استقرار فقط به یک سازمان دولتی تعلق دارد، بنابراین فیلتر سراسری چندسازمانی نمی‌سازیم.

## چیزهایی که عمداً وجود ندارند

- **هیچ** endpoint، Controller یا UI آماده مصرف کاربر اضافه نمی‌شود؛ `reference-host` در این فاز یعنی نمونه کد **تستی میزبان**.
- Gateway و Scanner این بسته `Phase12Fixture*` هستند و فقط داخل فایل تست قرار گرفته‌اند. اسکنر، ویروس‌یاب واقعی نیست. Gateway هیچ API یا کیف پول واقعی ندارد.
- هیچ migration، Scheduler، Queue، worker، عملیات واقعی مرکزی، داده شخصی واقعی یا تغییر پکیج قبلی افزوده نمی‌شود.
- هنوز تست‌های MySQL/PostgreSQL، race دو پردازشی، HTTP/SSO، اتصال API واقعی مرکزی، backup و اجرای Production باقی‌اند.

## چرا اکنون بدون نصب قابل نگهداری است؟

همه فایل‌ها فقط **جدید** هستند: یک تست در Sandbox، مستندات و ابزار بررسی استاتیک. هر سه پچ `Billing`, `Service Requests`, `Audit` باید قبل از اجرای این تست در Sandbox نصب شده باشند و Migration مربوط به `spatie/laravel-activitylog` باید در دیتابیس تست موجود باشد. در حال حاضر نیازی به اجرای هیچ‌کدام نیست.

فهرست قراردادها در `CONTRACT_MATRIX_FA.md`، نقشه آزمون‌ها در `TEST_MATRIX_FA.md` و ترتیب راه‌اندازی آینده در `DEFERRED_INSTALL_FA.md` قرار دارند. ابزار `tools/phase12/verify-readiness.php` صرفاً فایل‌ها را بررسی می‌کند و در حالت `--source-only` هیچ نیاز به اجرای Laravel یا اتصال بیرونی ندارد.
