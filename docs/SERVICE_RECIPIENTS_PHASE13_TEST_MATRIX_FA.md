# ماتریس تست فاز ۱۳ — Service Recipients

**سطح اعتبار:** تست‌های Core در بسته نوشته شده‌اند؛ تست‌های Laravel، مهاجرت و مسابقه تراکنش باید بعداً در Sandbox و DB مقصد اجرا شوند.

| سناریو | پوشش کد | تست تحویلی | نکته |
|---|---|---|---|
| پذیرش حقیقی/حقوقی | Core + policy میزبان | Core و لاراول | قوانین واقعی شناسه را میزبان پیاده‌سازی می‌کند |
| جست‌وجوی تکراری فقط در نمایندگی مالک | HMAC شامل شناسه نمایندگی + UNIQUE | Laravel | تست هم‌زمانی DB مقصد جدا لازم است |
| رمزگذاری اطلاعات | Laravel Crypt | Laravel | مدیریت کلید/دسترسی/بازشناسی API با میزبان |
| تغییر پروفایل و همگام‌سازی فقط پیش‌نویس‌های مجاز | Bridge اجباری | Laravel Fake | اتصال و Atomicity واقعی در فاز ۱۵ |
| تغییر شناسه فقط پس از تأیید Platform Admin | ثبت درخواست و تصمیم | Laravel | تست رقابت و audit واقعی در Sandbox ضروری است |
| منع نشت داده میان نمایندگی‌ها | Own-scope + Authorizer | Laravel | Policy میزبان نیز لازم است |
| بایگانی بدون درخواست ارسال‌شده باز | Host Bridge اجباری | Laravel Fake | race با ثبت درخواست تا نصب request gate رفع نمی‌شود |
| پیش‌نویس قدیمی بعد بازیابی قابل ویرایش نباشد | freeze فقط؛ بدون unfreeze | Laravel Fake | اجرای واقعی Freeze باید در فاز ۱۵ وصل شود |
| چند نماینده فعال شخص حقوقی | سقف هر مایکروسرویس | Laravel | تأیید اختیار و نماینده اختصاصی درخواست در Host/فاز ۱۵ |
| ثبت Audit بدون PII | رویداد با شناسه opaque | Laravel Fake | real audit transaction/Spatie باید جدا بررسی شود |
| سامانه خارجی، اعتبار مجدد و fallback | فقط طراحی/قرارداد میزبان | **هنوز ندارد** | این کار در فاز اتصال Host/Service Requests انجام شود |
| تست‌های یکپارچه NCR و دو استقرار مستقل | - | **هنوز ندارد** | پیش از Production الزامی |
