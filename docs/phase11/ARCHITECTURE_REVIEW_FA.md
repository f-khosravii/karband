# گزارش بازبینی معماری INTL Platform — ۲۰۲۶-۱۰-۰۲

## دامنه و سطح شواهد

- بررسی ایستای همه ۹ ZIP موجود: Workflow Core، Workflow Laravel، Authorization، Service Catalog، Dynamic Forms، Documents، Billing، Service Requests و Audit Laravel؛ مجموعاً ۲۱۱ مسیر فایل یکتا در بسته‌ها، شامل فایل‌های مشترک جدید برای `intl/contracts` و تست‌های Sandbox. پکیج `intl/contracts` از قبل در مخزن وجود دارد و `composer.json` اصلی آن همراه ZIPهای جدید دوباره بسته‌بندی نشده؛ ۱۴ مانيفست Composer پکیج‌های تحویلی بررسی شد.
- مقایسه محتوای هفت پچ اصلی موجود با ZIP متناظر از طریق بررسی معکوس `git apply --reverse --check` موفق بود. نسخه اصلی پچ Dynamic Forms و Documents در این محیط موجود نبود؛ نسخه‌های **بازسازی‌شده از ZIP** در کیت ضمیمه شده‌اند و جای فایل اصلی تأییدشده کاربر را نمی‌گیرند.
- همه ۱۶۶ فایل PHP موجود در مجموعه ZIP بازبینی‌شده از بررسی نحوی PHP 8.4.23 عبور کردند؛ ۱۲ اسکریپت smoke/demo بدون وابستگی به Laravel با خروج موفق اجرا شدند. این‌ها جای `composer install`، PHPUnit واقعی، تست ارتباط با پایگاه داده واقعی یا تست امنیتی عملیاتی نیستند.
- شواهد اجرای قبلی توسط کاربر: ۴۵ تست / ۸۲ assertion در ریشه (پس از Workflow)، ۱۱۱ تست / ۲۰۳ assertion در Sandbox (پس از Documents)، و ۱۱ تست / ۱۴ assertion هسته Documents. این شواهد فقط مراحل نصب‌شده در آن زمان را پوشش می‌دهد، نه سه فاز جدید.
- مجموعه ZIP اولیه `IntlDocumentsTest.php` هنوز اتصال `ActorResolver` و `WorkflowAuthorizer` را ندارد. کاربر آن را در مخزن خودش دستی اصلاح کرده و ۱۱۱ تست موفق گرفته است. پچ اصلاح تست قبلی برای **مخزن تمیز** در آرشیو حفظ شده؛ روی پروژه اصلاح‌شده دوباره اعمال نشود (از تکرار import و خطای Fatal پیشگیری شود).

## نتیجه ساختاری

۱. **وابستگی Composer:** در گراف ۱۴ پکیج تحویلی، وابستگی داخلی ناشناخته یا چرخه‌ای مشاهده نشد؛ تمام نیازمندی‌های `intl/*` یا در همین بسته‌ها وجود دارند یا به `intl/contracts` موجود ارجاع می‌دهند. ثبت `dev-main` در پکیج‌ها برای دوره توسعه فعلی قابل توضیح است، ولی طرح انتشار مستقل نسخه‌گذاری‌شده هنوز نیازمند تصمیم و اجرای واقعی است.

۲. **استقلال سازمان‌ها:** فایل‌های پکیج‌های Laravel از Connection پیکربندی‌شده میزبان استفاده می‌کنند. در ساختار فعلی هیچ پایگاه داده، کاتالوگ یا سرویس احراز هویت اجباری مشترک بین سازمان‌ها تعریف نشده است. تنها وابستگی زمان‌اجرای بیرونی عمدی، `CentralPaymentGateway` برای پرداخت مرکزی است؛ هنوز implementation عملیاتی ندارد.

۳. **یک منبع برای وضعیت:** Service Requests وضعیت مستقلی تعریف نمی‌کند و در خواندن درخواست به Workflow وصل می‌شود. فرم و مدارک به نسخه رزروشده درخواست متصل می‌شوند. ایجاد اتمیک اولیه به یک Connection دیتابیس محلی مشترک برای Request/Catalog/Workflow/Forms/Documents احتیاج دارد؛ مقدار پیکربندی یکسان به‌تنهایی کافی نیست، باید Connection واقعی یکسان تأیید شود.

۴. **کنترل دسترسی:** قراردادهای مشترک و Laravel Authorization برای انتخاب نقش، دسترسی و Scope جدا هستند. Government Admin در مایکروسرویس خودش نیازی به فیلتر چندسازمانی ندارد؛ Agency به Scope پرونده خودش محدود است؛ Platform Admin نیازمند Permission صریح است؛ مشتری نمایندگی User نیست. پیاده‌سازی Policy/Scope واقعی هر مایکروسرویس الزامی و خارج از پکیج عمومی است.

۵. **Audit:** تنها رویدادهای منتخب کسب‌وکار به Spatie Activitylog سپرده می‌شوند؛ تاریخچه Workflow همچنان مرجع تغییر وضعیت است. Audit انتخابی جای گزارش کامل Query Builder یا حفاظت رمزنگارانه در برابر دست‌کاری را نمی‌گیرد.

## فهرست ریسک‌ها و اقدام موردنیاز

| اولویت | موضوع | وضعیت و اقدام |
|---|---|---|
| **مانع پرداخت واقعی** | قرارداد مرکزی | تا دریافت API واقعی، semantics `idempotency`، استعلام همان کلید، معنای نتیجه قطعی و واحد پول روشن نشده است، `CentralPaymentGateway` عملیاتی Bind نشود. نتایج نامشخص را شکست قطعی یا دستور برداشت دوباره فرض نکنید. |
| **قبل از Release Candidate** | پوشش تست مراحل جدید | Billing، Service Requests و Audit هنوز در Sandbox واقعی کاربر اجرا نشده‌اند. اجرای تست‌های جدا و ترکیبی پس از نصب، روی دیتابیس تست مستقل ضروری است. |
| **قبل از انتشار نسخه** | مدیریت نسخه Composer | نیازهای بین‌پکیجی بر اساس `dev-main` تعریف شده‌اند. تصمیم بین انتشار هماهنگ Monorepo و انتشار مستقل با repository/split و tag واقعی باید ثبت شود؛ از جایگزینی خودسرانه قیود قبل از ایجاد نسخه منتشرشده خودداری شود. `composer.lock` مستقل هر مایکروسرویس حفظ شود. |
| **قبل از نصب Documents از صفر** | Fixture تست | ZIP اولیه Documents فاقد bridge تست Workflow است. فقط اگر فایل تست هنوز اصلاح نشده، پچ Fix قبلی اعمال شود؛ هر دو روش اصلاح دستی و پچ هم‌زمان ممنوع است. |
| **قبل از اجرای هر محیط واقعی** | پیکربندی میزبان | Bindingهای PrincipalProvider، ScopeChecker، ActorResolver، WorkflowAuthorizer، RecipientVerifier، ReplacementPolicy و FileSafetyScanner واقعی و Fail-Closed باشند. Guardهای فرم و مدارک و TrustedQuoteProvider مخصوص هر خدمت تعریف شوند. |
| **قبل از استقرار روی DB هدف** | هم‌زمانی | SQLite تست‌های عملکردی برای اثبات قفل واقعی و رقابت بین پردازش‌ها کافی نیست. تست MySQL/InnoDB یا PostgreSQL با دو فرایند و rollback لازم است. |
| **قبل از Audit واقعی** | schema و نگهداری | Migration خود Spatie منتشر شود؛ برای Userهای UUID/ULID نوع ستون `causer_id` تطبیق داده شود. سیاست نگهداری، دسترسی خواندن و امکان دست‌کاری DB مستقلاً تصویب شود. رویدادهای انتخابی در نقطه درست عملیات فراخوانی شوند؛ نصب پکیج به‌تنهایی رویدادها را ثبت نمی‌کند. |
| **قبل از مهاجرت NCR** | تفاوت وضعیت و داده | تطبیق status/code قبلی، مالکیت نمایندگی، پرداخت‌های نامشخص، تاریخچه و درخواست‌های باز در قالب مهاجرت مستقل انجام شود. این گزارش جایگزین ممیزی نسخه زنده NCR نیست. |

## نتیجه و مرز ادعای سازگاری

- **تأییدشده ایستا:** گراف بدون چرخه در Composer Manifestهای تحویلی، عدم تداخل مسیر فایل ZIPها، یکتایی نام فایل‌های Migration داخلی، نحوی PHP و smokeهای محلی.
- **تأییدشده از خروجی کاربر:** تست‌های بخش‌های تا Documents در Sandbox قبلی او؛ وضعیت فعلی مخزن کاربر مستقلاً دریافت یا اجرا نشده است.
- **هنوز تأییدنشده:** حل وابستگی‌های کل پکیج‌ها با Composer در یک نصب تازه، اجرای Laravel/PHPUnit برای سه بسته آتی، مهاجرت دیتابیس‌های مقصد، صحت API پرداخت مرکزی، مقاومت واقعی در برابر race، امنیت فایل‌اسکنر واقعی، رفتار عملیاتی و اتصال NCR.

**حکم اجرایی:** این فاز یک بسته ممیزی و برنامه نصب تولید می‌کند، نه مجوز نصب Production و نه الزام به تغییر کد فعلی پکیج‌هایی که تست موفق داشته‌اند.

## بررسی کتابخانه‌های بیرونی (منابع عمومی، مستقل از کد تحویلی)

در زمان این بازبینی، صفحه Packagist نسخه `spatie/laravel-permission 8.3.0` را با وابستگی Laravel/Illuminate 13 و PHP `^8.3` نشان می‌دهد، و `spatie/laravel-activitylog 5.1.1` را با وابستگی Laravel/Illuminate 13 و PHP `^8.4`. این اطلاعات با قیود `^8.0` و `^5.1` در ZIPهای ما هم‌راستاست؛ اما حل نهایی Composer و تداخل احتمالی سایر وابستگی‌های پروژه فقط در محیط نصب و با `composer.lock` واقعی مشخص می‌شود.

## بازپخش ترتیب کامل Patchها در محیط مصنوعی

پس از بررسی اولیه، تمام پچ‌های فازهای قبلی در یک پوشه Git **مصنوعی و خالی** و به ترتیب نصب بازپخش شدند: هفت پچ اصلی موجود، دو پچ بازسازی‌شده از ZIP برای Forms و Documents، پچ Fix تست Documents برای نصب تمیز، و پچ افزایشی اسناد/ابزار فاز ۱۱. هر یازده پچ در `git apply --check` و `git apply` موفق بودند. تطابق ۲۱۱ وقوع فایل آرشیو با فایل بازپخش‌شده بررسی شد؛ تنها تفاوت، اصلاح عمدی fixture تست Documents بود. **این آزمایش اثبات سازگاری با وضعیت و تغییرات محلی Git کاربر نیست**؛ در نصب واقعی هر مرحله باید `git apply --check` مجدداً اجرا شود.
